# Design Spec: chez-libuv v0.1

- **Date:** 2026-08-18
- **Status:** Accepted (2026-08-18) — Stage 0 spike complete
  (`spike/FINDINGS.md`); see [ADR index](#2-decisions-summary)
- **Supersedes:** nothing. Refines `.plans/chez-http-server-architecture.md` §1
  (the transport-layer box in that diagram)
- **Scope:** v0.1 of the Chez Scheme binding for libuv

This document specifies `chez-libuv` v0.1: a thin FFI binding from Chez Scheme
to libuv's event loop, TCP, and timer APIs. Each decision below is backed by an
ADR under `.plans/decisions/`, which carries the alternatives considered and
the consequences; this document specifies the resulting system.

---

## 1. Goal and non-goals

**Goal.** Provide a legible, low-level mirror of libuv's asynchronous I/O
primitives — event loop, TCP sockets, timers — as an R6RS library
`(libuv ...)`, packaged `chez-libuv`. "Legible mirror" means the public API
follows libuv's own verb set (`accept` / `read` / `read-stop` / `read-start` /
`write` / `timer` / `close`) closely enough that a caller who knows libuv
recognizes the Scheme surface immediately, and so that the server layer above
this binding can implement its own backpressure and connection-state policy
directly against these primitives rather than against an opinionated
abstraction this binding would otherwise have to design and justify.

**Non-goals.**

- **No HTTP.** This binding parses nothing and understands no protocol above
  raw bytes. HTTP/1 parsing and connection semantics belong to the sibling
  `chez-http1` and `chez-http-server` projects (`.plans/chez-http-server-architecture.md`).
- **No DNS, process, or filesystem bindings.** v0.1 covers exactly the event
  loop, TCP, and timers; every other libuv subsystem is out of scope until a
  later version motivates it.
- **No Windows CI.** The design stays portable (§4, §10), but v0.1 verifies
  only Linux and macOS ([ADR-0004](decisions/0004-windows-deferred-design-clean.md)).
- **No zero-copy I/O.** Every buffer crosses the FFI boundary by copy in v0.1
  ([ADR-0009](decisions/0009-copy-at-the-boundary.md)); the public API shape
  reserves room for a zero-copy variant later without a breaking change.

```
  libuv-shim.c / libuv-shim.h   # constant getters + debug counters ONLY (+ bulk byte moves, #35)
  libuv.sls                     # (libuv) facade: re-exports + uv-version(-compatible?)
  libuv/
    loop.sls                    # (libuv loop)

    tcp.sls                     # (libuv tcp)
    timer.sls                   # (libuv timer)
    private/
      config.sls                # generated by make, gitignored
      conditions.sls             # &uv-* hierarchy (pure, (rnrs) only)

```

`test-facade.sps` imports `(libuv)` and nothing else that could supply one of
the facade's own names, so a dropped re-export fails the suite at expand time
— the export list is otherwise guarded by nothing, since every other suite
imports the underlying library directly (added at Stage 2).

The shim artifact is `build/lib/libchezlibuv.{dylib,so}`; `CHEZ_LIBUV_SHIM`
overrides its path at runtime.

`private/` holds every module that ever touches a native pointer or a raw
`uv_*` symbol. Nothing outside `private/` sees a pointer: `libuv/handle.sls`,
`libuv/tcp.sls`, and `libuv/timer.sls` expose only records and procedures over
Scheme values.

## 4. native.sls rules

`native.sls` is the single FFI library and the only file reviewed for direct
libuv symbol bindings. It follows four fixed rules, adapted from the
`chez-cmark-gfm` harness and tightened for the callback axis that project
never needed:

1. **Path resolution is validated, never searched.** `resolve-shim-path`
   accepts an absolute, existing, regular-file path — either the
   `CHEZ_LIBUV_SHIM` environment override or the path baked into generated
   `config.sls` — and raises `&uv-shim-unavailable` on anything else. There is
   no fallback search and no bare-name `dlopen`.
2. **Load order is a hard invariant.** libuv's own shared object is loaded
   explicitly, by absolute path, *before* the shim. On Linux, `dlopen`
   namespaces are per-object rather than global, and this binding calls
   `uv_*` symbols directly ([ADR-0002](decisions/0002-direct-ffi-with-constants-only-shim.md)),
   so those symbols must already be resolvable in the process before the
   shim — and every `foreign-procedure` declaration after it — is evaluated.
3. **`load-shared-object` is a `define` placed before every `foreign-procedure`
   binding.** Entry points resolve when the defining expression is evaluated,
   not on first call (`AGENTS.md`'s named trap); getting the ordering wrong
   fails at import time, far from the mistake.
4. **Pointer types are uniform.** Every handle, request, and buffer pointer
   crossing the boundary is declared `uptr`. `nread` (the read callback's
   signed byte count, which also carries `UV_EOF` and negative error codes)
   is declared `ssize_t`, confirmed by spike Q3 to be a native Chez foreign
   type — and confirmed load-bearing there, since binding it unsigned routes
   `UV_EOF` into the data path as `2^64 − 4095`. `define-ftype` is used for
   exactly one type, `uv_buf_t` — the only libuv struct this binding
   constructs rather than merely receiving a pointer to.

The eight callback trampolines (§8) are declared here as `foreign-callable`s,
but their bodies are mechanical: look up the dispatcher slot for that
callback's *type* — one of the eight fixed names, not the firing pointer —
and call it. The slots themselves are filled exactly once, by `handles.sls`,
via `install-callback-dispatchers!` — a second call asserts. The registry
lookup that resolves the firing handle or request's `uptr` to its entry
happens one step later, inside `handles.sls`' seam closure, once dispatch has
already left this file. This keeps the one FFI-reviewed file free of both
dispatch policy and the registry lookup itself.

Initialization is gated: `ensure-native-loaded!` (mutex'd, idempotent)
snapshots the shim's constant table into `(libuv private constants)` records,
builds the int→symbol errno table, and validates the `uv_buf_t` ftype
declaration against the shim's `sizeof`/`offsetof` getters before anything
else runs — a range check between the shim's compiled `UV_VERSION_HEX` and
the runtime `uv_version()`, not equality, since libuv guarantees ABI stability
across its 1.x series. Any of these failing fails the whole library closed,
before a single handle can be created.

## 5. Handle lifecycle state machine

Every handle (TCP or timer) moves through exactly three states:

```
                    %make-uv-tcp / %make-uv-timer
                              │
                              ▼
                 alloc-zeroed (uv_*_size) + uv_*_init
                 nonzero rc ⇒ free immediately + raise
                 (nothing registered yet)
                              │
                              ▼
                        ┌───────────┐
                        │   open    │  public ops gated by require-open
                        └─────┬─────┘  (else &uv-handle-closed)
                              │
                              │ uv-close! — idempotent by state test,
                              │ stores the on-close callback
                              ▼
                        ┌───────────┐
                        │  closing  │  private dispatchers still tolerate
                        └─────┬─────┘  this state: in-flight request
                              │        callbacks (e.g. 'ECANCELED writes)
                              │        land here — libuv guarantees every
                              │        request callback fires before
                              │        close_cb, and close_cb fires last
                              │
                              │ close dispatcher, the ONLY place that frees
                              │ the handle pointer:
                              │   pop registry entry → free read buffer
                              │   → free handle pointer → zero the stored
                              │   uptr → transition to 'closed
                              ▼
                        ┌───────────┐
                        │  closed   │  the user's on-close callback runs
                        └───────────┘  AFTER this transition, under guard,
                                       so touching the handle from inside
                                       on-close deterministically raises
                                       &uv-handle-closed
```

**The registry is the GC root.** One global `eqv-hashtable` maps `uptr` to
registry entry, for both handles and requests (discriminated by a `kind`
field; entries carry a loop backpointer for filtering). An open handle and
its stored closures stay reachable through this table for as long as it is
open, even if the caller drops every other reference to it — closing is
therefore never GC-timed ([ADR-0007](decisions/0007-no-guardians-explicit-close.md)).
A handle the caller never closes leaks deterministically and visibly, via the
debug counters (§10) and Valgrind, rather than being silently reclaimed at
some later, indeterminate GC.

**Loop operations**, in `(libuv loop)`:

- `make-uv-loop` / `uv-run` (modes `'default` / `'once` / `'nowait`; rejects
  re-entrant `uv-run` calls via a `running?` flag)
- `uv-stop!`
- `uv-loop-close!` — fails with `'EBUSY` (as a symbol, per §9) if handles
  remain open; frees and zeroes the loop pointer; idempotent
- `uv-loop-teardown!` — close every registered handle on this loop, drain the
  loop until they finish closing, then `uv-loop-close!`; implemented against
  the registry filtered by loop backpointer, since no `uv_walk` binding
  exists in v0.1
- `call-with-uv-loop` — `dynamic-wind` is valid here, unlike around an
  individual handle, because loop teardown is synchronous once entered; a
  handle's `uv-close!` is not (its completion is a later callback), so no
  `dynamic-wind` wraps a handle's lifetime

## 6. Read path

`uv-read-start!` allocates one reusable buffer per handle via `foreign-alloc`
(default 64 KiB), so the `alloc_cb` libuv invokes on every read is infallible
— it hands back an already-allocated pointer, never allocates on the hot
path. This buffer is freed in exactly one place: the close dispatcher, never
earlier, because Windows' overlapped-read model can still reference it after
a read completion is queued but before the handle has fully stopped (this
also keeps the buffer's lifetime rule uniform across platforms ahead of
[ADR-0004](decisions/0004-windows-deferred-design-clean.md)).

The read dispatcher delivers data to the caller's `on-data` callback as a
**fresh copy**, shaped `(bv start end)` rather than a bare bytevector — a
span, so a future zero-copy variant can hand back a sub-range of a larger
buffer without changing the call shape
([ADR-0009](decisions/0009-copy-at-the-boundary.md)). `nread`
values are dispatched as:

- `0` — ignored (libuv's "nothing to read this time" signal, not EOF)
- `UV_EOF` — delivered as `(on-eof)`, a distinct callback, never wrapped in an
  error condition ([ADR-0006](decisions/0006-error-codes-are-symbols.md))
- any other negative value — delivered as `(on-error condition)`, the
  condition passed as a plain object, never raised across the callback
  boundary (§8); the binding never auto-closes the handle on a read error

Backpressure is `uv-read-stop!` / `uv-read-start!`, reusing the stored buffer
and callbacks; both are explicitly legal to call from inside `on-data` itself
(§8).

## 7. Write path

`(uv-write! tcp bv [start end] on-complete)` validates its arguments before
allocating anything. On success it performs exactly one `foreign-alloc`,
sized for `[uv_write_t | pad | uv_buf_t | payload copy]` in a single block,
and registers a request entry in the registry keyed on that block's `uptr`. A
nonzero return from `uv_write` deregisters the entry, frees the block, and
raises immediately — nothing is left half-registered.

The write-done dispatcher pops the request entry and frees the block **before**
invoking `(on-complete err)`, where `err` is `#f` on success or a condition
object — notably `'ECANCELED` when the write loses a race against the handle
closing. The caller's bytevector is free to be reclaimed the instant
`uv-write!` returns: the copy into the foreign-alloc'd block is complete by
then, and the Scheme heap never backs an in-flight write.

Vectored (scatter-gather) writes are deferred — the copying design makes
multiple source buffers equivalent to one concatenated copy — with the name
`uv-write*!` reserved for that API. `uv-shutdown!` and `uv-tcp-connect!`
follow the same request-allocation pattern; the connect request is
co-allocated with its `sockaddr_storage`.

## 8. Callback boundary discipline

Every one of the eight trampoline bodies (§4, §10) is guarded: nothing raised
inside a callback is permitted to unwind into libuv's C stack frames.

The policy is **store-and-reraise**: the first value a guard catches is
stored on the loop's `pending-error` cell, and `uv_stop` is called on that
loop. Callbacks already queued for this iteration still run, still guarded;
any further raises are appended to a `deferred-errors` list, readable via
`uv-loop-deferred-errors` and cleared at the start of the next `uv-run`.
`uv-run` itself re-raises the stored error, wrapped as `&uv-callback-error`
**composed with** the original condition object, so a guard written against
the original condition type still matches. This wrapped re-raise on the way
out of `uv-run` is the one sanctioned deliberate-escape path in the whole
binding: raise inside a callback, catch around `uv-run`.

**Why store-and-reraise, given that propagation actually works.** Stage 0
spike Q2 (`spike/FINDINGS.md`) measured what a Scheme `raise` crossing a libuv
C stack frame does, and refuted this design's original premise. A raise *does*
propagate through libuv's C frames into a `guard` established outside the
blocking `uv_run`, condition type and fields intact, and the loop object
survives — a second `uv_run` afterwards runs normally and teardown returns `0`.
The policy is kept anyway, for two measured reasons:

- **Escaping leaves an invisible cleanup obligation.** The abandoned
  iteration's *event* survives: after escaping from a read callback (invoked
  from deep inside `uv__io_poll`), draining the loop with the handles still
  open and the read still started **redelivered the pending `UV_EOF` in full**,
  and that late delivery ran the EOF branch the escape had skipped. What did
  not happen is the callback's own work: at escape time that branch had not
  run, the handles it would have closed stayed open, and nothing re-runs the
  loop automatically. A caller who treats the raise as terminal and goes
  straight to teardown gets `-16 (EBUSY)` from `uv_loop_close` and no
  explanation. Escaping from a timer callback left nothing observable
  outstanding, with a single active handle — a residue that varies with
  libuv's internal call depth is not something a caller can reason about.
- **An unguarded raise terminates the process** (exit `255`, no teardown, no
  `uv_loop_close`, no `foreign-free`). Guarding every trampoline body is
  therefore mandatory regardless of which delivery policy is chosen.

Store-and-reraise buys determinism and a defined post-error loop state — not
safety from an impossible unwind, and not rescue of lost events. `uv_run`
returns through its own C epilogue and the caller gets a loop they can close;
that every callback already queued for that iteration runs is a property of
letting the iteration finish, not a Q2 measurement. See
[ADR-0008](decisions/0008-static-trampolines-and-handle-registry.md).

**Legal from inside a callback:** `uv-close!`, `uv-read-start!` /
`uv-read-stop!`, `uv-write!`, `uv-shutdown!`, accepting a connection
(required inside `on-connection`), creating a new handle, timer operations,
`uv-stop!`, `uv-now`, `uv-update-time!` (issue #28 — calling it from a
callback that held the loop is its purpose).

**Illegal from inside a callback:** `uv-run`, `uv-loop-close!`,
`uv-loop-teardown!` — each raises `&uv-invalid-argument` if called while the
loop that owns the callback is already running.

## 9. Condition hierarchy

```
&uv-error                                  ; root condition, no fields
├─ &uv-errno-error (errno code message)    ; errno: symbol via uv_err_name_r
│                                          ; code: raw platform int, preserved
│                                          ; message: uv_strerror_r
├─ &uv-handle-closed (kind)                ; kind: 'tcp | 'timer | 'loop
├─ &uv-shim-unavailable (path)
├─ &uv-version-incompatible (compiled runtime)
├─ &uv-constant-unavailable (name)
├─ &uv-invalid-argument (who reason)
└─ &uv-callback-error (cause)              ; composed with cause when cause
                                            ; is itself a condition (§8)
```

`errno` lives on `&uv-errno-error` specifically, not on the `&uv-error` root —
a root-level field that is meaningful for some subtypes and absent or
meaningless for others is exactly the truthiness trap `AGENTS.md` documents
for accessor results in general.

These are the same condition record types delivered as plain objects to
asynchronous callbacks (`on-error`, `on-complete`'s `err` argument) and raised
synchronously from procedures that fail immediately. A caller never sees a
raw FFI integer; every negative `uv_*` return code is translated at the
boundary ([ADR-0006](decisions/0006-error-codes-are-symbols.md)).

## 10. GC invariants

Each invariant below is paired with the test or counter that enforces it
(§11); none is a comment-only rule, per `AGENTS.md`'s "prefer a check to a
comment."

- **Locked objects are exactly the eight static trampolines**, `lock-object`'d
  once, in one file (`native.sls`), for the process lifetime — never one per
  handle or per request
  ([ADR-0008](decisions/0008-static-trampolines-and-handle-registry.md)).
- **Everything else native-side is `foreign-alloc`'d**: loops, handles,
  request-plus-payload blocks, read buffers, connect-request `sockaddr`
  scratch. libuv never holds a pointer into the Scheme heap.
- **Bytevectors cross the FFI only as `u8*` arguments to synchronous calls**
  that complete before the call returns — never stored by libuv for later use
  ([ADR-0009](decisions/0009-copy-at-the-boundary.md)).
- **Each allocation kind is freed in exactly one place**, and the freeing
  site zeroes the stored `uptr` immediately (§5, §6, §7).
- **Debug counters** (`CHEZ_LIBUV_DEBUG_COUNTERS`, dev builds only; classes:
  `loop`, `tcp`, `timer`, `write_req`, `connect_req`, `read_buffer`) let tests
  assert `live-counts` return to baseline after teardown — asserted nonzero
  mid-test first, per the sentinel rule, so a counter stuck at zero throughout
  cannot pass by accident
  ([ADR-0003](decisions/0003-linux-valgrind-is-the-sole-memory-gate.md)).

## 11. Testing strategy

Framework: SRFI-64. Every suite owns its runner and ends with
`(exit (if (zero? fail) 0 1))` as its literal last line — `AGENTS.md`'s named
trap for suites that report green through real failures because SRFI-64 sets
no process exit status on its own. `tests/uv-testing.sls` provides `run-until`
(step `uv-run 'once` up to a bounded iteration count until a predicate holds;
failure is iteration exhaustion, never wall-clock elapsed time) plus loopback
connection plumbing shared across suites.

- **TCP has no external client.** Every TCP test binds `127.0.0.1:0`, reads
  the real ephemeral port back via `uv_tcp_getsockname`, and connects to it
  from the same loop and process — deterministic, free of port collisions,
  and entirely visible to a single Valgrind run
  ([ADR-0010](decisions/0010-loopback-integration-tests-replace-differential-oracle.md)).
  Subprocess clients are rejected by design.
- **Timers never depend on wall-clock timing.** 0/1/5 ms timeouts are driven
  by `'once`-stepping (which blocks until the next timer is due), asserting
  invocation counts and order rather than elapsed time; a 1-hour timer
  checked against `'nowait` proves "didn't fire early"; a stop-after-3-fires
  test proves determinism. Every timer callback calls `(collect)`, exercising
  GC pressure on the re-entrant callback path on every single run rather than
  as a special case.
- **Suites:** `test-conditions` (pure hierarchy discrimination, both
  directions), `test-native` (path-resolution matrix, version-boundary
  cases at floor−1/floor/ceiling/ceiling+1, constant distinctness and
  positivity, a bogus constant name raising the documented condition, an
  errno round-trip over the full enumeration), `test-shim-loading` plus its
  subprocess probe (one subprocess per environment scenario, adapted from
  the cmark-gfm harness), `test-loop` (empty-loop return values, `'EBUSY` as
  symbol *equality*, never truthiness, use-after-close sentinels, stopping a
  loop from inside a callback), `test-timer`, `test-tcp` (bind, getsockname,
  listen, accept, connect, write, read, EOF, `'ECONNRESET`,
  `'ECONNREFUSED`, read-stop/read-start backpressure, a chunked 1 MiB
  transfer), `test-lifecycle` (counters asserted mid-test nonzero, then
  balanced: after an ordinary close, after a callback raises, after 100
  iterations plus `(collect)`; the registry is empty after close_cb; a
  deferred-error re-raise leaves the loop usable afterward), `test-echo`
  (the capstone — 8 concurrent in-process clients, each sending 32 KiB of
  seeded-random payload across 3 chunks, compared byte-for-byte, followed
  by graceful teardown with all counters at zero), `test-facade` (the
  `(libuv)` re-export list — guarded at expand time by importing the facade
  and nothing that could substitute for one of its names, since every other
  suite imports the underlying library directly and would keep passing after
  an export was dropped; plus `uv-version` cross-checked against
  `uv_version()`, a second entry point rather than a restatement).
- `check-purity` runs every suite that does not require native loading with
  `CHEZ_LIBUV_SHIM=/nonexistent`, proving those suites have no hidden native
  dependency.
- Each implementation stage produces a mutation log
  (`.plans/stage-N-mutation-log.md`): every new assertion is watched to fail,
  by name, under a mutation that breaks the specific property it claims to
  guard, then confirmed to pass again on revert (`AGENTS.md`).
